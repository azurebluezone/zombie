What this console is contract

This is a third-party UI. It has no build step in the runtime, no shared source, and no server-side include. Delete this folder and the runtime keeps working — that is a test, not a promise.

Every value on screen comes from an HTTP response. The tag live means the value was fetched in this session; unverified means it was not.

For remote use put TLS in front (nginx/Caddy), keep ADMIN_TOKEN set, and add this page's origin to CORS_ALLOW_ORIGINS.

Why masking exists what it does / does not do

It gives clients a stable identity

A client asks for zombiecoder/code-guru and keeps that id even when the upstream model changes. Provider names, upstream model ids, keys and routing are removed from responses and from the public catalog, so switching from Gemini to Groq is an operator edit, not a client migration.

It is not anonymity from you

The operator can always see the route on this page and in the admin API. Masking is a boundary between the client protocol and the runtime's internals, not a secret kept from the person running the server. It also does not rewrite provider names the model itself writes into prose.

Test it below: the third module, Provider masking, takes a canonical response with provider: gemini and returns the same response with model: zombie-mini and no provider field.

What this page can and cannot do boundaries

Writes go through the documented admin endpoints, one record at a time:

POST /v1/admin/personas PATCH /v1/admin/personas/{id} DELETE /v1/admin/personas/{id} (soft: sets enabled=false) PUT /v1/admin/agent-model-mappings/{agentId} DELETE /v1/admin/agent-model-mappings/{agentId}

An agent itself is registry-owned. This page shows its status and boundary; disabling it sends DELETE /v1/admin/registry/agents/{id} (soft disable), it never deletes the file that defines the agent.

Masking, in one minute client identity vs operator route

What a client can see and send
model: zombiecoder/code-guru GET /v1/models → only zombiecoder/* ids response / SSE metadata → no provider name errors → no upstream model id credentials → none; the key never leaves the runtime
What only the operator can see
agent-model-mappings: code-guru → gemini-2.5-flash provider row: gemini · key fingerprint only the router's candidate list and priority

An agent does not “know” the provider. An agent is a persona plus a server-side route; the route is operator state and is never part of the client contract. Masking does not hide traffic from the operator, and it cannot rewrite a provider name that the model writes into its own prose — it masks the protocol metadata, not free text.

Registered tools –

The switch sends PATCH /v1/admin/registry/tools/{id} with status: DISABLED. Execution only accepts REGISTERED/ENABLED/VERIFIED, so a disabled tool cannot run even if a request names it. Access mode: — — unrestricted means no per-application grant is needed; permissioned requires one.
